# Gateway and Service Orchestration

Orkes Conductor workflows can be exposed as APIs and can orchestrate the services they depend on. Gateway gives applications and AI agents a single entry point to your workflows, as an HTTP route or an MCP tool, with authentication and access control applied. Service Orchestration is how a workflow calls the external HTTP and gRPC services it depends on. You register each service once, and every workflow reuses it, with execution history recorded for every call.

## Gateway: Expose workflows as APIs or MCP tools

Gateway lets applications and AI agents call a workflow. You group routes under a service, link each route to a workflow, and set the authentication for the service. When a request arrives, Conductor runs the workflow and returns its output. Retries, branching, human steps and the full execution history come with the workflow.

A Gateway service is one of two types:

- [API Gateway](/content/developer-guides/api-gateway): Exposes a workflow as APIs that applications and internal services call.
- [MCP Gateway](/content/developer-guides/mcp-gateway): Exposes a workflow as MCP tools that AI agents discover and call.

## Service Orchestration: Call external services

Workflows call external HTTP and gRPC services through [Remote Services](/content/remote-services). You register a service once, with its address, authentication and endpoints. Workflows then pick a call from the catalog instead of repeating URLs and headers. You can also register schemas and add a circuit breaker.

## Which one do I need

- An application or agent should trigger a workflow: Gateway, with an API or MCP service.
- A workflow should call an external HTTP or gRPC service from several places: Remote Services.
- A workflow makes a one-off external call: Use an [HTTP task](/content/reference-docs/system-tasks/http) directly.

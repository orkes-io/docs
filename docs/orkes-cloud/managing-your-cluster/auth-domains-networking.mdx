# Manage Cluster Authentication, Domains & Networking

This page covers how to change your cluster's authentication method, add or remove subdomains for your Conductor UI, and enable the API Gateway.

## Change your cluster's authentication type

By default, your cluster uses ***Default Orkes Authentication***. You can switch it to use your organization's identity provider through OpenID Connect (OIDC) instead.

Before you begin, set the callback URL on your identity provider to match your authentication type:

1. Generic OpenId Connect: `https://<conductor domain>/login/oidc/callback`
2. Okta OIDC Connect: `https://<conductor domain>/login/callback`

#### To change the authentication type from Orkes Cloud portal:

1. From your cluster's detail view, select the **Authentication** tab.
2. Select **Change Authentication Type**.
3. From the **Authentication Type** dropdown, select your identity provider: **Generic OpenId Connect** for any OIDC-compliant provider, or **Okta OIDC Connect** for Okta specifically.
4. Enter the fields for your selected provider. All fields are required.

   **Generic OpenId Connect:**

   | Parameter | Description |
   | --- | --- |
   | Audience | Usually present in the token generated by the OIDC provider as one of the claims (`aud`). In some cases, this is the same as the client ID. |
   | Client Id | Available in the authorization URL. |
   | Issuer | The JWT token issuer. |
   | OIDC Configuration URL | Your provider's OpenID configuration URL, for example `https://domain/.well-known/openid-configuration`. |
   | Email Claim | The JWT claim field containing the user's unique email address. Defaults to `email`; customize it if your provider uses a different claim name. |

   **Okta OIDC Connect:**

   | Parameter | Description |
   | --- | --- |
   | Audience | Usually present in the token generated by Okta as one of the claims (`aud`). In some cases, this is the same as the client ID. |
   | Client Id | Available in the authorization URL. |
   | Issuer | The JWT token issuer. |

5. Select **Confirm**.

## Add/remove sub-domain

If you're using your own domain for your cluster, you can add extra hostnames that point to your Conductor UI, for example, adding `staging.yourdomain.com` alongside your primary `app.yourdomain.com`. This is only available for clusters using a domain you brought yourself; it isn't available for clusters using an Orkes-managed domain, or for Orkes Hosted clusters.

What you add here is another way to reach your existing Conductor UI, and not a way to register a separate endpoint like a Grafana or webhook URL.

### Add a sub-domain

1. From your cluster's detail view, select the **URLs** tab.
2. Select **Add Another**.
3. Enter the sub-domain label you want to add; lowercase letters, numbers, and hyphens only (for example, `staging`). Orkes appends it to your cluster's existing domain.
4. Select **Confirm**.

Orkes automatically provision a new TLS certificate and DNS record for the new hostname; no action is needed on your end. This takes a few minutes to complete and propagate.

### Remove a sub-domain

1. From the **URLs** tab, select **Delete** next to the sub-domain you want to remove.
2. Type the full hostname to confirm.

You can't remove a sub-domain if it's the only one your cluster has; at least one UI hostname must always remain.

## Enable the API Gateway

**Note**: This action is only available on AWS, and Azure clusters.

Your cluster can run an API Gateway in front of it.

1. From your cluster's detail view, open **Select an Action** and choose **Enable API Gateway.**
2. Review what enabling it will deploy: an InfluxDB instance for metrics collection, the API Gateway's ingress configuration, a DNS record at `api.<your cluster domain>`, an SSL certificate, and Route53 DNS configuration. This creates additional cloud resources and may take several minutes to complete.
3. Select **Enable API Gateway.**

Learn more about [Orkes Conductor’s Gateway](/content/reference-docs/api/gateway) feature.

# Manage Cluster Authentication

Your cluster's **authentication type** controls how users log in to your Conductor cluster. You can use one of two types:

- **Default Orkes Authentication**: Users are managed through role-based access control (RBAC) in Orkes Conductor.
- **Generic OpenId Connect**: Users log in through any configured OIDC-compliant identity provider.
- **Okta OIDC Connect** (deprecated): Use Generic OpenId Connect instead.

Changing the type updates the cluster's Conductor deployment. This page covers how to switch to your organization's identity provider, and the fields each provider needs.

## Before you begin

Set the callback URL on your identity provider to `https://<conductor domain>/login/oidc/callback`.

## Default Orkes Authentication

Clusters are usually provisioned with Default Orkes Authentication, so this is the type your cluster uses until you switch it.

How the first users get access depends on who provisions the cluster:

- **Customer Hosted clusters**: The user who provisions the cluster is added to it automatically as an Admin.
- **Orkes Hosted clusters**: Orkes provisions the cluster for you, and the initial admins you share with Orkes team are added to your cluster.

After that, an Admin grants everyone else access through [RBAC in Orkes Conductor](/content/access-control-and-security/users-and-groups#users).

## Change authentication type

#### To change the authentication type from Orkes Cloud portal:

1. From your cluster's detail view, select the **Authentication** tab.
2. Select **Change Authentication Type**.
3. From the **Authentication Type** dropdown, select your identity provider: **Generic OpenId Connect** for any OIDC-compliant provider, including Okta.
4. Enter the fields for your selected provider. All fields are required.

    **Generic OpenId Connect:**

    | Parameter | Description |
    | --- | --- |
    | Audience | Usually present in the token generated by the OIDC provider as one of the claims (`aud`). In some cases, this is the same as the client ID. |
    | Client Id | Available in the authorization URL. |
    | Issuer | The JWT token issuer. |
    | OIDC Configuration URL | Your provider's OpenID configuration URL, for example `https://domain/.well-known/openid-configuration`. |
    | Email Claim | The JWT claim field containing the user's unique email address. Defaults to `email`; customize it if your provider uses a different claim name. |

    **Okta OIDC Connect:**

    | Parameter | Description |
    | --- | --- |
    | Audience | Usually present in the token generated by Okta as one of the claims (`aud`). In some cases, this is the same as the client ID. |
    | Client Id | Available in the authorization URL. |
    | Issuer | The JWT token issuer. |

5. Select **Confirm**.

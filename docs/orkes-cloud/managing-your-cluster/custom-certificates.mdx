# Manage Custom Certificates

A **custom certificate** is a certificate authority (CA) certificate that you upload to your cluster so the Orkes-managed Workers component trusts connections secured by it. Workflows sometimes call a service secured by a private or internal CA, such as an internal API, through an HTTP task. Without a custom certificate, these calls fail TLS validation because the Workers component doesn't recognize that CA.

Uploading a custom certificate adds it to the Workers component’s custom trust store, so HTTP tasks can connect to systems signed by that CA without disabling certificate validation. Public certificate authorities remain trusted.

In the Orkes Cloud portal, you can upload, view, and delete a certificate from a cluster.

## Upload a certificate

1. From your cluster's detail view, open **Select an Action** and choose **Upload Certificate**.
2. In the **Upload Certificate** dialog, select **Browse** and choose the certificate file. Accepted file types are `.crt`, `.cer`, `.ca-bundle`, `.p7b`, `.p7c`, `.p7s`, and `.pem`.
3. Select **Confirm**.

Uploaded certificates are applied to the Workers component.

### What happens after upload

Orkes schedules the certificate for installation and mounts it as a custom trust store for the Workers component. Uploading a certificate restarts the Workers pods. On the **Certificates** tab, the certificate’s state shows its progress.

## View certificates

From your cluster's detail view, select the **Certificates** tab to see all certificates uploaded to the cluster, listed with their file name, alias, path, and state.

## Delete a certificate

1. From the **Certificates** tab, find the certificate you want to remove. It must show a state of **Ready** to be deleted.
2. Select the delete icon next to it.
3. In the **Delete Certificate** dialog, type the certificate's alias when prompted, then select **Confirm**.

Deleting a certificate removes it from the custom trust store. If your workflows still need to reach the service it was trusting, upload a replacement certificate first to avoid connection failures.

**Note**: Orkes doesn’t track the expiry date of uploaded certificates, and doesn’t flag them when they’re close to expiring. If the certificate on the other end gets renewed or replaced, upload the new one and delete the old one yourself.

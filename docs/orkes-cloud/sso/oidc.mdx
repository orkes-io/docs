# Configure Single-Sign-On (SSO) with OpenID Connect (OIDC)

Orkes supports **any OIDC-compliant identity provider** as your identity provider. This doc covers the generic path. If your provider has a dedicated setup doc (such as Microsoft Entra ID or Okta), use that one instead.

:::note
Once you configure SSO with OIDC, the cluster's current login method **stops working**. Before you make this change, make sure at least one user is both an Admin on the Conductor cluster and a user in your OIDC provider with the same email address, or you could lock yourself out of the cluster entirely.
:::

## OIDC provider setup

In your OIDC provider's console, register an application for your Conductor cluster. The exact steps vary by provider, but you'll need to end up with a client ID, an audience, an issuer, and a metadata URL to use in the steps below.

Set the authorized redirect URL to your cluster's URL with the path `/login/oidc/callback` (for example, `https://<your-cluster-domain>/login/oidc/callback`). You can find your cluster's URL on the URLs tab of the cluster details page once you're in the Orkes Cloud portal.

## Changing authentication via Orkes Cloud portal

Use the Cloud portal to configure your Conductor cluster's authentication:

1. Go to **Clusters**, and select your cluster.
2. Go to the **Authentication** tab.
3. Select **Change Authentication Type**.
4. From the **Authentication Type** dropdown, select **Generic OpenId Connect**.
5. Fill in the following fields:
    1. **Audience**: Usually present in the token generated by the OIDC provider as one of the claims (aud). In some cases this is the same as the client ID.
    2. **Client Id**: The ID generated when you registered the application with your OIDC provider.
    3. **Issuer**: The JWT token issuer.
    4. **OIDC Configuration URL**: Your provider's OpenID configuration URL.
    5. **Email Claim**: The JWT claim field that holds the user's unique email ID. This defaults to "email", but you can customize it if your provider uses a different claim.
6. Select **Confirm**.

Wait for the change to take effect in the cluster, usually within 5 to 10 minutes. Force-refresh your browser to see the new authentication type. If you see errors, try using an incognito window.

# Configure Single-Sign-On (SSO) with Microsoft Entra ID

Orkes supports **Microsoft Entra ID** as your identity provider through an OIDC connection. Setting this up involves registering an application in Entra ID, then using the Cloud portal to configure your Conductor cluster to use it.

:::note
Once you configure SSO with Microsoft Entra ID, the cluster's current login method **stops working**. Before you make this change, make sure at least one user is both an Admin on the Conductor cluster and a user in Entra ID with the same email address, or you could lock yourself out of the cluster entirely.
:::

Orkes does not create users when someone signs in with SSO. Every person who signs in must already exist in the cluster (**Access Control** → **Users**) with the same email address as in Entra ID. SSO controls who can authenticate, and the user's role in the cluster controls what they can do.

## Creating an application in Microsoft Entra ID

In this section, you [register an application in Microsoft Entra ID](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), then copy the values Orkes needs to connect to it: the Application (client) ID, the OpenID Connect metadata document, the issuer, and, if your tokens need one, an email claim.

1. In the Azure portal, open **Microsoft Entra ID** and go to the overview page of the tenant you want to integrate with.
2. Select **App registrations** from the left menu.
3. Register a new application:
    - Enter a name.
    - Choose from the supported account types, for example **Accounts in this organizational directory only (Single tenant)**.
    - For **Redirect URI**, select **Single Page Application** and enter `https://<your-cluster-url>/login/oidc/callback`, using the URL from your cluster's **URLs** tab in the Cloud portal. You can change this value later if you don't have it now.
4. Register the application.
5. Go to **API permissions** and select **Grant admin consent for** `<your tenant>`. An Entra administrator must do this once.
6. Open the registered application.
7. Select **Authentication (Preview)**, then the **Settings** tab, and under **Implicit grant and hybrid flows**, make sure **ID tokens** is selected, and save your changes.
8. Go to **Overview** and copy and store the **Application (client) ID**.

Next, copy the metadata document, then build the issuer from your tenant ID:

<ol start="9">
<li>Select <strong>Endpoints</strong> from the top navigation and copy the <strong>OpenID Connect metadata document</strong> value, <code>https://login.microsoftonline.com/&lt;tenantid&gt;/v2.0/.well-known/openid-configuration</code>, which is the <strong>OIDC Configuration URL</strong> you'll enter in Orkes.</li>
<li>The <strong>Issuer</strong> isn't shown in Entra ID. Enter <code>https://login.microsoftonline.com/&lt;tenantid&gt;/v2.0</code> as the <strong>Issuer</strong> in Orkes, replacing <code>&lt;tenantid&gt;</code> with your <strong>Directory (tenant) ID</strong>.</li>
</ol>

Next, make sure your users have an email:

<ol start="11">
<li>Every user who signs in must have an email set in Microsoft Entra ID (<strong>Users</strong> → select the user → <strong>Edit properties</strong> → <strong>Contact information</strong> → <strong>Email</strong>). Users without an email can't sign in.</li>
</ol>

:::info Note
If your DNS name or IP address changes, add it to the application registration's **Authentication** > **Redirect URI** list.
:::

## Changing authentication via Orkes Cloud portal

To switch to this authentication method:

1. Go to the [Orkes Cloud portal](https://cloud.orkes.io/) and select the cluster you're updating.
2. Go to the **Authentication** tab and select **Change Authentication Type**.
    1. Choose **Generic OpenId Connect** and enter the values from the previous section:
        1. **Audience**: The Application ID (the same value as Client ID).
        2. **Client Id**: The Application ID. (Audience and Client ID are the same value for Microsoft Entra ID).
        3. **Issuer**: The issuer from step 10, in the format `https://login.microsoftonline.com/<tenantid>/v2.0`.
        4. **OIDC Configuration URL**: The metadata document URL from step 9, in the format `https://login.microsoftonline.com/<tenantid>/v2.0/.well-known/openid-configuration`.
        5. **Email Claim**: email (the pre-filled default).
3. Select **Confirm**.

Wait for the change to take effect in the cluster, usually within 5 to 10 minutes. Until the rollout finishes, some sign-ins may still use the previous login method. Force-refresh your browser to see the new authentication type. If you see errors, try using an incognito window.

# Configure Single-Sign-On (SSO) with Microsoft Entra ID

Orkes supports Microsoft Entra ID as your identity provider through an OIDC connection. Setting this up involves registering an application in Entra ID, then using the Cloud portal to configure your Conductor cluster to use it.

**Note**: Once you configure SSO with Microsoft Entra ID, the cluster's current login method stops working. Before you make this change, confirm that at least one user who will have Admin access on the Conductor cluster can successfully log in through Entra ID, or you could lock yourself out of the cluster entirely.

## Creating an application in Microsoft Entra ID

1. In the Azure portal, open **Microsoft Entra ID** and go to the overview page of the tenant you want to integrate with.
2. Select **App registrations** from the left menu.
3. Register a new application:
   - Enter a name.
   - Choose from the supported account types. The default option is **Accounts in any organizational directory (Any Microsoft Entra ID tenant - Multitenant)**.
   - For **Redirect URI**, select **Single Page Application** and enter `https://[your cluster DNS hostname or IP]/login/oidc/callback`. You can change this value later if you don't have it now.
4. Register the application.
5. Open the registered application.
6. Select **Authentication** from the left menu.
7. Under **Implicit grant and hybrid flows**, make sure **ID tokens (used for implicit and hybrid flows)** is selected.
8. Save your changes.
9. Go to **Overview** and copy the **Application (client) ID**.
10. Optional, only required if the JWT token generated by Azure AD doesn't contain an email claim: if none of the existing claims include an email address, add one:
    - Go to **Token Configuration** from the left menu.
    - Select **Add optional claim**.
    - Select **Token Type** = **ID**.
    - Select the **email claim** that contains an email address.
11. From the Entra ID home page, select **App registrations** from the left menu.
12. Select **Endpoints** from the top navigation and copy the **OpenID Connect metadata document** value.
13. Open this endpoint in a new window and find the **issuer** field. Copy this value. If it's a templated URL, for example `https://login.microsoftonline.com/{tenantid}/v2.0`, replace the templated variable with the actual value; you can find the tenant ID in the console as **Directory (tenant) ID**.

After completing these steps, you'll have the following values, which you'll use to configure Conductor to point to Azure AD as the identity provider:

1. Application (client) ID
2. OpenID Connect metadata document
3. Issuer
4. The claim for the user's email ID, or the custom token claim that represents it, if you configured one

**Notes**

- The first time you log in, your admin might need to authorize this application.
- If your DNS name or IP address changes, add it to the application registration's **Authentication** > **Redirect URI** list.

## Changing authentication via Orkes Cloud portal

To switch to this authentication method:

1. Go to the [Orkes Cloud portal](https://cloud.orkes.io/) and select the cluster you're updating.
2. Go to the **Authentication** tab and select **Change Authentication Type**.
   1. Choose **Generic OpenId Connect** and enter the values from the previous section:
      1. **Audience**: The Application ID.
      2. **Client Id**: The Application ID. Audience and Client ID are the same value for Azure AD.
      3. **Issuer**: The issuer value. Use the actual URL, not the templated value.
      4. **OIDC Configuration URL**: The OpenID Connect metadata document.
      5. **Email Claim**: The email claim.
3. Select **Confirm**.

Wait for the change to take effect in the cluster, usually within 5 to 10 minutes. Force-refresh your browser to see the new authentication type. If you see errors, try using an incognito window.

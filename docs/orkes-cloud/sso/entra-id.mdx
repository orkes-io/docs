# Configure Single-Sign-On (SSO) with Microsoft Entra ID

Orkes supports **Microsoft Entra ID** as your identity provider through an OIDC connection. Setting this up involves registering an application in Entra ID, then using the Cloud portal to configure your Conductor cluster to use it.

:::note
Once you configure SSO with Microsoft Entra ID, the cluster's current login method **stops working**. Before you make this change, make sure at least one user is both an Admin on the Conductor cluster and a user in Entra ID with the same email address, or you could lock yourself out of the cluster entirely.
:::

## Creating an application in Microsoft Entra ID

In this section, you [register an application in Microsoft Entra ID](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), then copy the values Orkes needs to connect to it: the Application (client) ID, the OpenID Connect metadata document, the issuer, and, if your tokens need one, an email claim.

1. In the Azure portal, open **Microsoft Entra ID** and go to the overview page of the tenant you want to integrate with.
2. Select **App registrations** from the left menu.
3. Register a new application:
    - Enter a name.
    - Choose from the supported account types, for example **Accounts in any organizational directory (Any Microsoft Entra ID tenant - Multitenant)**.
    - For **Redirect URI**, select **Single Page Application** and enter `https://[your cluster DNS hostname or IP]/login/oidc/callback`. You can change this value later if you don't have it now.
4. Register the application.
5. Open the registered application, and select **Authentication** from the left menu.
6. Under **Implicit grant and hybrid flows**, make sure **ID tokens (used for implicit and hybrid flows)** is selected, and save your changes.
7. Go to **Overview** and copy and store the **Application (client) ID**.

Next, copy the metadata document and issuer from the same application:

<ol start="8">
<li>Select <strong>Endpoints</strong> from the top navigation and copy the <strong>OpenID Connect metadata document</strong> value.</li>
<li>Open this endpoint in a new window and find the <strong>issuer</strong> field. Copy this value. If it's a templated URL, for example <code>https://login.microsoftonline.com/{tenantid}/v2.0</code>, replace the templated variable with the actual value; you can find the tenant ID in the console as <strong>Directory (tenant) ID</strong>.</li>
</ol>

Then add an email claim if your token doesn't have one:

<ol start="10">
<li>Optional, only required if the JWT token generated by Azure AD doesn't contain an email claim: if none of the existing claims include an email address, add one:
<ul>
<li>Go to <strong>Token Configuration</strong> from the left menu.</li>
<li>Select <strong>Add optional claim</strong>.</li>
<li>Select <strong>Token Type</strong> = <strong>ID</strong>.</li>
<li>Select the <strong>email claim</strong> that contains an email address, then select <strong>Add</strong>.</li>
</ul>
</li>
</ol>

:::info Note
If your DNS name or IP address changes, add it to the application registration's **Authentication** > **Redirect URI** list.
:::

## Changing authentication via Orkes Cloud portal

To switch to this authentication method:

1. Go to the [Orkes Cloud portal](https://cloud.orkes.io/) and select the cluster you're updating.
2. Go to the **Authentication** tab and select **Change Authentication Type**.
    1. Choose **Generic OpenId Connect** and enter the values from the previous section:
        1. **Audience**: The Application ID.
        2. **Client Id**: The Application ID. (Audience and Client ID are the same value for Azure AD).
        3. **Issuer**: The issuer value. Use the actual URL, not the templated value.
        4. **OIDC Configuration URL**: The OpenID Connect metadata document.
        5. **Email Claim**: The email claim.
3. Select **Confirm**.

Wait for the change to take effect in the cluster, usually within 5 to 10 minutes. Force-refresh your browser to see the new authentication type. If you see errors, try using an incognito window.

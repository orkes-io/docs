# Connect Conductor Cluster with AWS PrivateLink

AWS PrivateLink lets you set up **private connectivity** between your network and your Conductor cluster, in either direction, using the same underlying service. Depending on your needs, you can set up:

- **User network → Conductor cluster**, to remove public internet access to your cluster
- **Conductor cluster → User network**, so your workflows can reach private services on your side, such as internal APIs through HTTP tasks or message queues like Kafka

You can set up one direction or both.

## Prerequisites

- An Orkes-hosted AWS cluster with a VPC

## User network → Conductor cluster

Orkes creates an Endpoint Service (the side being reached) in front of your Conductor cluster, in the same AWS region as your cluster, and shares the service name and endpoint service DNS name with you. You create an Endpoint (the side that connects to it) in your own VPC, then set up your own private DNS to route your cluster's DNS name through it.

:::note
Orkes sets up PrivateLink in the same AWS region as your Conductor cluster. Only VPCs in that region can use the connection directly. To reach it from VPCs in other regions, you'll need to set up peering and routing rules to route the connection through the VPC where your Endpoint is running.
:::

### Share your AWS account ID

1. Give Orkes the AWS account ID you'll use to create your Endpoint.
2. Orkes will notify you with the Endpoint Service name and Endpoint Service DNS name.

### Select your VPC

1. In the AWS Console, switch to the same region as your Conductor cluster.
2. Select the VPC you want to connect to the PrivateLink.
3. Make sure the VPC has **DNS hostnames** and **DNS resolution** enabled.

### Create your Endpoint

You'll now [create an Endpoint](https://docs.aws.amazon.com/vpc/latest/privatelink/create-endpoint-service.html#connect-to-endpoint-service) in your VPC that connects to the Endpoint Service Orkes set up in front of your Conductor cluster.

1. Go to **VPC > Endpoints > Create endpoint**.
2. Enter a name for your endpoint.
3. For **Type**, select **Endpoint services that use NLBs and GWLBs**.
4. For **Service name**, enter the service name Orkes provided, and click **Verify service**.
    - If you see "Service name could not be verified," confirm you're in the correct region and that your account ID matches what you gave Orkes. If both check out, reach out to Orkes.
5. Once verified, select your VPC from which you'll access the endpoint service.
6. Select availability zones (2 or 3, depending on your cluster size) and the corresponding subnets.
7. Select the **IPv4** address type and the **IPv4** DNS record IP type.
8. Select a security group that allows HTTPS (443) traffic.
9. Click **Create endpoint**.

Your endpoint is created in a **Pending acceptance** state. Let Orkes know once you've created it so we can accept the connection request.

### Set up DNS

After Orkes accepts your connection, AWS provisions your endpoint.

1. On your endpoint, choose **Actions > Modify private DNS name**, and select **Enable for this endpoint**. This can take a few minutes.
2. Set up your own private DNS so your Conductor cluster's DNS name routes to this endpoint.

Once this is done, you'll be able to reach your Conductor cluster at its usual DNS name from within your VPC.

## Conductor cluster → User network

You create an Endpoint Service (the side being reached) on your side and share its details with Orkes. Orkes creates an Endpoint (the side that connects to it) in your cluster's VPC.

:::note
Your Endpoint Service must be set up in a VPC in the same AWS region as your Conductor cluster. If the service you want Orkes to reach lives in a different VPC than the one hosting your Endpoint Service, you'll need to set up peering and route tables from that VPC to the destination VPC.
:::

### Get Orkes's AWS account ID

Contact your Orkes representative to get the AWS account ID Orkes will connect from. You'll allow this account on your Endpoint Service in the next section.

### Create Endpoint Service

1. In the AWS Console, switch to the same region as your Conductor cluster.
2. Select the VPC you want to provision the Endpoint Service in.
3. Follow [AWS's instructions for creating an Endpoint Service](https://docs.aws.amazon.com/vpc/latest/privatelink/create-endpoint-service.html).
4. On your Endpoint Service, open **Allow principals** and add Orkes's AWS account ID.
5. Share the following with Orkes:

   | Field | Example |
   | --- | --- |
   | Your Conductor cluster's DNS name (the one that will call this Endpoint Service) | `customer-abc.orkesconductor.io` |
   | PrivateLink service name | `com.amazonaws.vpce.us-west-2.vpce-svc-xxxxxxxx` |
   | PrivateLink DNS name | `internal.yourcompany.com` |
   | The DNS name(s) your workflows will call through this connection | `internal-api.yourcompany.com` |
   | A testing URL (for HTTP/S), or bootstrap server host:port (for a message queue like Kafka) | `https://internal-api.yourcompany.com/health` |

### Accept the connection

Once Orkes creates the corresponding Endpoint, you must accept the connection request, unless you configured your Endpoint Service with auto-acceptance.

### What happens after

Orkes tests the connection and confirms with you once your outbound PrivateLink connection is validated and ready to use.

### Add a new DNS name to an existing connection

If you need another DNS name for a service behind a connection that's already in place, share the new DNS name with Orkes and we'll add a record for it. No new Endpoint is required.

# Getting Started with Orkes Cloud

## What is Orkes Cloud?

Orkes Cloud lets you deploy fully managed, dedicated Conductor clusters on the cloud provider of your choice. Rather than operating Conductor yourself, Orkes Cloud handles provisioning, scaling, and operations for you, including enterprise capabilities like role-based access control (RBAC), SSO, advanced analytics, and audit logs.

Orkes Cloud runs Orkes Conductor, the Enterprise version of the open source orchestration engine, with capabilities OSS doesn't have. On top of that, Orkes Cloud handles the operations, provisioning, scaling, upgrades, and monitoring, so you never have to stand up or run any of it yourself.

In short: if you're deploying Conductor to the cloud, Orkes Cloud is the vehicle that gets you there.

## What is the Cloud Portal?

The cloud portal, at [cloud.orkes.io](https://cloud.orkes.io/), is the web interface you use to set up, configure, and monitor your Orkes Cloud deployment. It's where you provision clusters, manage users and access, configure networking, monitor uptime and certificates, and perform administrative actions like upgrades or rollbacks.

## Cloud Portal vs. Conductor Cluster: What's the Difference?

It's easy to confuse the cloud portal with your Conductor cluster, but they serve different audiences and different purposes:

- **Cloud portal** is built for DevOps and platform teams, where you manage the infrastructure, such as provisioning clusters, configuring networking, managing users and SSO, monitoring health, and handling upgrades.
- **Conductor cluster**, which is your running Conductor instance, is built for developers. This is where you design and run workflows and agents, register task workers, and build on the Conductor APIs and SDKs.

Put simply: the cloud portal manages the deployment; the cluster is the product your developers actually build against.

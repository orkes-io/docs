# How to deploy a customer hosted cluster on GCP

Orkes Cloud can provision and manage a Conductor cluster inside your own Google Cloud project. This guide covers the prerequisites and steps to create a **customer hosted cluster** on GCP through the Orkes Cloud portal.

## Prerequisites

To create a customer-hosted cluster on GCP, you need the following:

- A GCP project you control, with billing enabled.
- The gcloud CLI installed and configured, or access to GCP Cloud Shell, to run the setup script Orkes generates.
- Permissions in that project to enable APIs, create a service account, and grant it a custom IAM role.
- If you're using an existing VPC from your own project, an empty, custom-mode VPC with no subnets.
- If you're using Shared VPC, someone on your network team who can run a setup script in the separate host project to create the VPC, subnet, and related resources.

## Steps to provision the cluster

If the **Create New Cluster** option isn't available to you in the portal, contact your Orkes representative.

#### To create a customer hosted cluster on GCP:

1. Log in to the [Orkes Cloud portal](https://cloud.orkes.io/).
2. Go to **Clusters** from the left navigation menu.
3. Select **Create New Cluster** > **Create New Customer Cluster**.
4. Select **Google Cloud** as the cloud provider.
5. Enter:
    1. **Cluster Name**: Max 18 characters. Letters, numbers, and hyphens only (can't start with a hyphen, and can't contain "google").
    2. **GCP Project ID**: Your GCP project ID.
    3. **GCP Region**: Select from the dropdown. Orkes supports the following:
        - US Central, Iowa (us-central1)
        - US East, South Carolina (us-east1)
        - US East, Virginia (us-east4)
        - US West, Oregon (us-west1)
        - US West, Los Angeles (us-west2)
        - US West, Salt Lake City (us-west3)
        - US West, Las Vegas (us-west4)
        - Canada, Montreal (northamerica-northeast1)
        - Canada, Toronto (northamerica-northeast2)
        - South America, São Paulo (southamerica-east1)
        - Europe West, Belgium (europe-west1)
        - Europe West, London (europe-west2)
        - Europe West, Frankfurt (europe-west3)
        - Europe West, Netherlands (europe-west4)
        - Europe West, Zurich (europe-west6)
        - Europe North, Finland (europe-north1)
        - Asia South, Mumbai (asia-south1)
        - Asia Southeast, Singapore (asia-southeast1)
        - Asia Southeast, Jakarta (asia-southeast2)
        - Asia East, Taiwan (asia-east1)
        - Asia East, Hong Kong (asia-east2)
        - Asia Northeast, Tokyo (asia-northeast1)
        - Asia Northeast, Osaka (asia-northeast2)
        - Asia Northeast, Seoul (asia-northeast3)
        - Australia, Sydney (australia-southeast1)
        - Australia, Melbourne (australia-southeast2)
6. Select **Generate GCP Setup Script**. This opens the Authorize GCP Account dialog:
    1. **Step 1, Download and Run Setup Script**: Download the script and run it with the gcloud CLI or in GCP Cloud Shell (bash setup-script.sh). It creates a dedicated service account, grants it a custom IAM role covering GKE, Compute Engine and networking, Cloud SQL, Memorystore, Secret Manager, Cloud Storage, Cloud KMS, Cloud DNS, IAM, logging, and monitoring, and outputs a JSON key.
    2. **Step 2, Paste Service Account JSON Key**: Paste the full JSON key the script outputs to the Orkes cloud portal, then select **Verify & Continue**.
7. Once verified, configure the cluster in the Orkes Cloud portal:
    1. **Domain Url**: Enter a subdomain and select a base domain. Only Orkes-managed domains are available for GCP; there's no option to use your own domain.
    2. **Preferred Availability Zones**: Select up to 3 zones within your chosen region. The GKE cluster spreads across them.
    3. **Ingress Type**: VPC Only (access via VPN or peering) or Internet (access using credentials).
    4. **Cluster Capacity**: Small, Medium, Large, Extra Large, or Optimized for High Performance. Each maps to a specific GKE machine type and node range, Redis size, and Postgres tier.
    5. **Environment Type**: Tag the cluster's environment (Production, Staging, Development, Test, or Proof of Concept).
    6. **Enable authentication**: Yes or No. Yes adds a default authorization configuration you can later change to your own OpenID Connect (OIDC) identity provider.
    7. **VPC Configuration:** Select one of the following:
        - **Create a new VPC**: Orkes provisions the VPC and subnets for you.
        - **Use an existing VPC from your project**: Select an empty, custom-mode VPC with no existing subnets.
        - **Use Shared VPC** (network managed in a separate host project): Enter the Host Project ID, then download a setup script for your network team to run once in that host project. It provisions the VPC, subnet, private service access, NAT, firewall rules, and IAM grants, and prints the resulting resource links. Paste back the VPC Self-Link, Subnet Self-Link, Pods Secondary Range Name, and Services Secondary Range Name it outputs.
8. For the **Create a new VPC** and **Use an existing VPC** options, you can optionally set (each has a default, so none are required):
    1. **VPC CIDR Range**: /16 to /24, a private RFC1918 range. Defaults to 10.0.0.0/16.
    2. **Pod CIDR Range**: The GKE pod IP range, /8 to /24. Defaults to 10.128.0.0/17. Immutable after provisioning.
    3. **PSC Prefix Length**: Size of the Private Service Connection IP block used for Cloud SQL and Redis, /16 to /24. Defaults to /16. Immutable after provisioning.
9. Select **Create Provisioning Workflow**. Provisioning typically completes within an hour.

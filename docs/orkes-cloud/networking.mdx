# Networking & Connectivity

By default, your Conductor cluster communicates **over the public internet**: your team logs in to Conductor through a public endpoint, and any HTTP tasks your workflows run reach external systems the same way. When your organization's security requirements call for keeping cluster traffic off the public internet, in either direction, Orkes supports private connectivity through your cloud provider's own networking primitives.

## Two directions of private connectivity

Private connectivity between your network and your Conductor cluster can run in either direction, and you can set up one or both, depending on your needs:

- **User network → Conductor cluster**: Your team and systems reach the Conductor cluster privately, without traffic leaving your cloud provider's network. This lets you disable the cluster's public-facing ingress entirely.
- **Conductor cluster → User network**: Your workflows reach private services on your side, such as internal APIs through HTTP tasks, without those services being exposed to the public internet.

## Choosing the right guide

The private networking technology you'll use depends on your cloud provider and which direction you need:

| Cloud provider | Technology | Directions supported |
| --- | --- | --- |
| AWS | AWS PrivateLink | Both directions, set up separately for each direction you need |
| Azure | Azure Private Link | Both directions, set up separately for each direction you need |
| GCP | GCP Private Service Connect | One-way per connection, set up separately for each direction you need. Use this if you only need one-way access. |

Setting up private connectivity is a collaborative process between the user and Orkes: some steps happen in your cloud account, others happen in ours, so your Orkes contact will work with you through each guide.

## Routing outbound traffic through a proxy

Separately from private connectivity, your organization may require all outbound requests, including those from Conductor's HTTP and HTTP Poll tasks, to pass through a proxy server. Orkes Conductor supports proxy configuration for these tasks, for both customer-hosted and Orkes Cloud-deployed clusters.

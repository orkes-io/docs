# Exporting Advanced Metrics to an External Monitoring Platform

You can send your Conductor cluster's metrics to an external observability platform, so you can monitor them alongside the rest of your stack. You set this up by adding the platform's connection details to your cluster as application properties. You don't need to change your workflows or workers.

Conductor uses [Micrometer](https://micrometer.io/) to collect metrics, so you can export to any of these platforms:

| Platform | Property prefix |
| --- | --- |
| Atlas | `management.atlas.metrics.export` |
| Azure Monitor | `management.azuremonitor.metrics.export` |
| CloudWatch | `management.cloudwatch.metrics.export` |
| Datadog | `management.datadog.metrics.export` |
| Dynatrace | `management.dynatrace.metrics.export` |
| Elasticsearch | `management.elastic.metrics.export` |
| Influx | `management.influx.metrics.export` |
| New Relic | `management.new-relic.metrics.export` |
| OpenTelemetry Protocol (OTLP) | `management.otlp.metrics.export` |
| StackDriver | `management.stackdriver.metrics.export` |
| StatsD | `management.statsd.metrics.export` |

Export to each platform is turned off by default. To turn it on, set `<property prefix>.enabled` to `true` and add the platform's connection properties.

## Prerequisites

- An Admin or Root role in your Orkes Cloud organization. Only these roles can run **Upgrade Deployment**.
- An account with your monitoring platform, and an API token that has permission to ingest metrics.

The steps below use Dynatrace as the example.

## Step 1: Create an API token in your monitoring platform

For Dynatrace, create an access token with the **metrics.ingest** scope, and note your environment URL and API keys.

## Step 2: Add the export properties to your cluster

1. In the [Orkes Cloud portal](https://cloud.orkes.io/), go to **Clusters** and select your cluster.
2. From the **Select an Action** dropdown, select **Upgrade Deployment**.
3. In **Resource Type**, select **Conductor Server**.
4. Leave the version field set to the version your cluster is running now, which is filled in for you. This step changes configuration only, so you don't need to change the version.
5. Under **Key-Value parameters**, select **+** once for each property in the table below, and enter its key and value.

   | Key | Example value | Description |
   | --- | --- | --- |
   | `management.dynatrace.metrics.export.enabled` | `true` | Turns on export to Dynatrace. |
   | `management.dynatrace.metrics.export.uri` | `https://<environment-id>.live.dynatrace.com/api/v2/metrics/ingest` | Your Dynatrace metrics ingest endpoint. |
   | `management.dynatrace.metrics.export.api-token` | `<your-api-token>` | The Dynatrace access token you created. |
   | `management.dynatrace.metrics.export.v2.metric-key-prefix` | `orkes.conductor` | A prefix added to every metric key, so you can find Conductor metrics in Dynatrace. |
   | `management.dynatrace.metrics.export.v2.default-dimensions.cluster` | `<your-cluster-label>` | Adds a `cluster` dimension to every metric, so you can filter or group metrics by cluster when you export from more than one cluster. Use any label that identifies this cluster to you in Dynatrace. It doesn't need to match the cluster's name in Orkes Cloud. |

6. Select **Confirm**.

## Step 3: Confirm the rollout

1. Open the **Actions History** tab and wait for the Upgrade Deployment action to finish.
2. Open the **Application Properties** tab and search for the properties you added to check that they're listed with the values you entered.

## Step 4: View your metrics in the monitoring platform

Metrics start arriving shortly after the rollout finishes. Each metric key starts with the prefix you set in Step 2, `orkes.conductor` in this example.

In Dynatrace, you can check which Conductor metrics are arriving by running this DQL query in a Notebook:

```
fetch metric.series
| filter startsWith(metric.key, "orkes.conductor")
| summarize count(), by:{metric.key}
```

The query returns one row for each metric key and the number of data points received for it in the selected timeframe. After you confirm that metrics are arriving, you can use them in Dynatrace dashboards and alerts like any other metric.

For the full list of metrics that Conductor publishes, see [Server Metrics](/content/developer-guides/metrics-and-observability).

## Using a different platform

The steps are the same for every platform. Only the properties you add in Step 2 are different. Start each property with your platform's prefix from the table at the top of this page, and set `<property prefix>.enabled` to `true`. To find the other properties for your platform, see the [Micrometer documentation](https://docs.micrometer.io/micrometer/reference/implementations.html). Your platform's documentation explains how to create the API key or token it needs.

## Stopping the export

To stop sending metrics, run **Upgrade Deployment** again with the **Conductor Server** resource type, and set `management.dynatrace.metrics.export.enabled` to `false`.

To remove a property completely, enter its key and leave the value empty. An empty value removes the property from your cluster.

# AWS Lambda Operations Reference

Orkes Conductor integrates with AWS Lambda to let you invoke and manage Lambda functions directly from your workflows. Once you configure the AWS Lambda integration, you can use the following operations to create, retrieve, update, and delete Lambda functions without leaving your workflow.

This page covers the parameters and expected output for each operation available in the [AWS Lambda integration](/content/integrations/aws-lambda).

## List Functions

Lists a page of Lambda functions in the configured AWS region.

<Tabs>
<TabItem value="input" label="Input Parameters">

| Parameter | Description | Type | Required/Optional |
| --------- | ----------- | ---- | ----------------- |
| Max Items | Maximum number of functions to return. Defaults to 50. | integer | Optional. |

</TabItem>
<TabItem value="output" label="Output Parameters">

Returns `count`, `nextMarker`, and a `functions` array where each entry contains `functionName`, `functionArn`, `runtime`, `role`, `handler`, `codeSize`, `description`, `timeout`, `memorySize`, `lastModified`, `codeSha256`, `version`, `state`, and `stateReason`. A nonempty `nextMarker` indicates another AWS result page; this operation does not expose a marker input for fetching subsequent pages.

</TabItem>
</Tabs>

## Create Function

Creates a new Lambda function from a base64-encoded ZIP package.

<Tabs>
<TabItem value="input" label="Input Parameters">

| Parameter | Description | Type | Required/Optional |
| --------- | ----------- | ---- | ----------------- |
| Function Name | Name of the Lambda function to create. | string | Required. |
| Runtime | Runtime environment. For example, `python3.12`, `nodejs22.x`, `java21`. | string | Required. |
| Role | ARN of the IAM role that Lambda assumes during execution. The integration identity must have `iam:PassRole` on this exact ARN; see [authentication and permissions](/content/integrations/aws-lambda#permissions-for-the-integration-identity).<br/><br/>**To create one**:<ol><li>Go to **IAM** > **Roles** > **Create role**.</li><li>Select **AWS service**, choose **Lambda**, and click **Next**.</li><li>Search for and attach **AWSLambdaBasicExecutionRole**, then click **Next**.</li><li>Enter a role name, for example `lambda-execution-role`, and click **Create role**.</li><li>Open the created role and copy the ARN. For example: `arn:aws:iam::123456789012:role/lambda-execution-role`.</li></ol> | string | Required. |
| Handler | Function entry point.<br/><br/>For example, `index.lambda_handler` for Python, `index.handler` for Node.js, or `com.example.Handler::handleRequest` for Java. | string | Required. |
| Zip File Base 64 | Function code as a base64-encoded ZIP file.<br/><br/> Create a ZIP of your code, then run `python3 -c "import base64; print(base64.b64encode(open('function.zip', 'rb').read()).decode())"` (Mac/Linux) or `[Convert]::ToBase64String([IO.File]::ReadAllBytes("function.zip"))` (Windows PowerShell) to get the encoded string.| string | Required. |
| Description | A description of the function's purpose. | string | Optional. |
| Memory Size | Memory allocated in MB (128–10240). Defaults to 128. | integer | Optional. |
| Timeout | Maximum execution time in seconds (1–900). Defaults to 3. | integer | Optional. |
| Environment Variables | Key-value pairs injected as environment variables, as a JSON string. For example, `{"KEY":"value"}`. | string | Optional. |

</TabItem>
<TabItem value="output" label="Output Parameters">

Returns the function's `status`, `functionName`, `functionArn`, `runtime`, `role`, `handler`, `codeSize`, `description`, `timeout`, `memorySize`, `lastModified`, `codeSha256`, `version`, and `state`.

</TabItem>
</Tabs>

## Invoke Function

Invokes a Lambda function synchronously or asynchronously with a JSON payload, or validates invocation permissions without running the function.

<Tabs>
<TabItem value="input" label="Input Parameters">

| Parameter | Description | Type | Required/Optional |
| --------- | ----------- | ---- | ----------------- |
| Function Name | Name of the Lambda function to invoke. | string | Required. |
| Payload | Input payload as a JSON string. For example, `{"message": "Hello from Lambda!"}`. | string | Required. |
| Invocation Type | The invocation type for the request. Supported values:<ul><li>`RequestResponse` for synchronous (waits for response)</li><li>`Event` for asynchronous (returns immediately)</li><li>`DryRun` to validate invocation parameters and permissions without executing the function</li></ul> Defaults to `RequestResponse`. | string | Optional. |

</TabItem>
<TabItem value="output" label="Output Parameters">

Returns `statusCode`, `requestId`, `response`, `functionError`, `error`, and `status`.

| Invocation type | Expected HTTP status | Result |
| --------------- | -------------------- | ------ |
| `RequestResponse` | `200` | Waits for the function result. A non-null `functionError` produces `status: "error"` and a failed Conductor task even though the HTTP status is 200. |
| `Event` | `202` | Returns `status: "accepted"`. Acceptance does not confirm that the asynchronous function execution succeeded. |
| `DryRun` | `204` | Validates the invocation without executing the function. |

For synchronous invocations, `response` contains parsed JSON when possible, otherwise the raw function output. `status: "rejected"` indicates an unexpected response status. `status: "unknown"` means Lambda did not confirm an invocation status; retrying may duplicate the invocation. Invocation failures are reflected in the Conductor task status; HTTP 200 alone is not a success check.

</TabItem>
</Tabs>

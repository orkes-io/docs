# AWS Lambda Integration with Orkes Conductor

:::info Notes
- **Available since:** v5.7.0 and later
- Connected Apps are enabled per cluster. If **Integrations > Connected Apps** is not in the left navigation, contact Orkes support to enable it.
:::

Integrating AWS Lambda with Orkes Conductor lets you build workflows that interact with your AWS Lambda using the following operations:

- List Functions
- Create Function
- Get Function Details
- Get Deployment Status
- Update Function Configuration
- Invoke Function
- Delete Function

This guide explains how to set up and use the integration. Here's an overview:

1. Get the required credentials from AWS.
2. Configure a new AWS Lambda integration in Orkes Conductor.
3. Use AWS Lambda integration in workflows.

## Step 1: Get the AWS credentials

Orkes Conductor supports three authentication types for AWS Lambda: access keys, assume role, and the Conductor role. Get the credentials for the type you want to use.

### Using access keys

For authenticating using access keys, get the Access Key ID and Secret Access Key of an IAM user. Optionally, also get a Session Token for temporary credentials.

**To create an IAM user and generate access keys:**

1. Log in to the [AWS Console](https://console.aws.amazon.com) and search for **IAM** in the top search bar.
2. In the left navigation, go to **Access Management** > **IAM Users**.
3. Select an existing user or select **Create user** to create a new one.
4. Select the user, go to the **Security credentials** tab, scroll to **Access keys**, and select **Create access key**.
5. For **Use case**, select **Application running outside AWS** and complete the creation flow.
6. On the final screen, copy the **Access key** and **Secret access key**. Store these securely as the secret access key is shown only once.

**To attach IAM policy to the user:**

1. Go to **Access Management** > **IAM Users** and select your user.
2. Go to the **Permissions** tab, and select **Add permissions** > **Create inline policy**.
3. Switch to the **JSON** tab, and paste a policy granting at minimum: `lambda:InvokeFunction`, `lambda:ListFunctions`, `lambda:GetFunction`, `lambda:CreateFunction`, `lambda:UpdateFunctionConfiguration`, `lambda:DeleteFunction`, and `iam:PassRole`. For example:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "lambda:ListFunctions"
          ],
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": [
            "lambda:InvokeFunction",
            "lambda:GetFunction",
            "lambda:CreateFunction",
            "lambda:UpdateFunctionConfiguration",
            "lambda:DeleteFunction"
          ],
          "Resource": "arn:aws:lambda:*:*:function:*"
        },
        {
          "Effect": "Allow",
          "Action": [
            "iam:PassRole"
          ],
          "Resource": "arn:aws:iam::*:role/lambda-execution-role"
        }
      ]
    }
    ```

    Replace `lambda-execution-role` with the name of the execution role you plan to use in the **Role** field of **Create Function**. If the names don't match, Create Function is denied.

4. To create functions from a ZIP archive in Amazon S3, also grant `s3:GetObject` on the bucket objects, and `s3:GetObjectVersion` if you specify an object version.
5. Give the policy a name and select **Create policy**.

### Using assume role

For authenticating using the assumed role, get the ARN of an IAM role that Conductor can assume, and the external ID set in that role's trust policy.

**To create the role and get its ARN and external ID:**

1. In the AWS Console, go to **IAM** > **Policies** and select **Create policy**.
2. Switch to the **JSON** tab, and paste a policy granting at minimum: `lambda:InvokeFunction`, `lambda:ListFunctions`, `lambda:GetFunction`, `lambda:CreateFunction`, `lambda:UpdateFunctionConfiguration`, `lambda:DeleteFunction`, and `iam:PassRole`. For example:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "lambda:ListFunctions"
          ],
          "Resource": "*"
        },
        {
          "Effect": "Allow",
          "Action": [
            "lambda:InvokeFunction",
            "lambda:GetFunction",
            "lambda:CreateFunction",
            "lambda:UpdateFunctionConfiguration",
            "lambda:DeleteFunction"
          ],
          "Resource": "arn:aws:lambda:*:*:function:*"
        },
        {
          "Effect": "Allow",
          "Action": [
            "iam:PassRole"
          ],
          "Resource": "arn:aws:iam::*:role/lambda-execution-role"
        }
      ]
    }
    ```

    Replace `lambda-execution-role` with the name of the execution role you plan to use in the **Role** field of **Create Function**. If the names don't match, Create Function is denied.

3. To create functions from a ZIP archive in Amazon S3, also grant `s3:GetObject` on the bucket objects, and `s3:GetObjectVersion` if you specify an object version.
4. Give the policy a name and select **Create policy**.
5. Go to **IAM** > **Roles** and select **Create role**.
6. For **Trusted entity type**, select **Custom trust policy**.
7. In the **Custom trust policy** editor, paste a trust policy that allows the Conductor worker role to assume this role, with an `sts:ExternalId` condition. For example:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Principal": {
            "AWS": "arn:aws:iam::<AWS account ID>:role/<Cloud Environment Tag>-worker-role"
          },
          "Action": "sts:AssumeRole",
          "Condition": {
            "StringEquals": {
              "sts:ExternalId": "<external ID>"
            }
          }
        }
      ]
    }
    ```

    The external ID is a value you choose. Use the same value in [Step 2](/content/integrations/aws-lambda#step-2-add-an-integration-for-aws-lambda). Select **Next**.

8. On **Add permissions**, select the policy created in step 4 and select **Next**.
9. Give the role a name and select **Create role**.
10. Open the role and copy its **ARN** from the summary page.

## Step 2: Add an integration for AWS Lambda

After obtaining the credentials, add an AWS Lambda integration to your Conductor cluster.

**To create an integration:**

<ol>
<li>Go to <strong>Integrations</strong> &gt; <strong>Connected Apps</strong> from the left navigation menu on your Conductor cluster.</li>
<li>Select <strong>+ New integration</strong>.</li>
<li>In the <strong>Cloud</strong> section, choose <strong>AWS Lambda</strong>.</li>
<li>Select <strong>+ Add</strong> and enter the following parameters:</li>
</ol>

| Parameter | Description | Required/Optional |
| --------- | ----------- | ----------------- |
| Integration name | A name for the integration. | Required. |
| Authentication | The authentication mode. Supported types:<ul><li>**Access Key** to authenticate with an AWS access key.</li><li>**Conductor Role (worker identity)** to authenticate with the identity of the Orkes Conductor worker.</li><li>**Assume Role (from worker identity)** to assume an IAM role, using the worker identity as the source.</li></ul> | Required. |
| Access Key ID | The AWS Access Key ID generated from [Step 1](/content/integrations/aws-lambda#using-access-keys). | Required if Authentication is *Access Key*. |
| Secret Access Key | The Secret Access Key generated from [Step 1](/content/integrations/aws-lambda#using-access-keys). | Required if Authentication is *Access Key*. |
| Session Token | The AWS session token for temporary credentials.<br/><br/>If you use temporary credentials, enter the Access Key ID, Secret Access Key, and Session Token from the same output. To get them, run `aws sts get-session-token --duration-seconds 43200` in the AWS CLI and copy `AccessKeyId`, `SecretAccessKey`, and `SessionToken`.<br/><br/>If you use long-lived access keys, leave this field empty. | Optional. |
| Role ARN | The ARN of the IAM role you created in [Step 1](/content/integrations/aws-lambda#using-assume-role) for Conductor to assume. | Required if Authentication is *Assume Role*. |
| External ID | The external ID required to assume the role, from [Step 1](/content/integrations/aws-lambda#using-assume-role). | Required if Authentication is *Assume Role*. |
| Description | A description of the integration. | Required. |

<ol start="5">
<li>(Optional) Toggle the <strong>Active</strong> button off if you don't want to activate the integration instantly.</li>
<li>Select <strong>Save</strong>.</li>
</ol>

The integration is created successfully.

## Step 3: Use AWS Lambda integration in workflows

Once the integration is ready, this can be used directly within the workflows.

**To use AWS Lambda integration in a workflow:**

<ol>
<li>Go to <strong>Definitions</strong> &gt; <strong>Workflow</strong> from the left navigation menu on your Conductor cluster.</li>
<li>Select <strong>+ Define workflow</strong>.</li>
<li>In your workflow, select the (<strong>+</strong>) icon and select <strong>Connected Apps</strong>.</li>
<li>In <strong>Add Task</strong> panel on the right, search for <strong>AWS Lambda</strong>, and select the integration created in <a href="/content/integrations/aws-lambda#step-2-add-an-integration-for-aws-lambda">Step 2</a>.</li>
</ol>

The following operations are available for use with this integration.

| Operation | Description |
| --------- | ----------- |
| [List Functions](/content/integrations/aws-lambda-operations#list-functions) | Lists the Lambda functions in a region of your AWS account. |
| [Create Function](/content/integrations/aws-lambda-operations#create-function) | Creates a new Lambda function from a base64-encoded ZIP package or a ZIP archive in Amazon S3. |
| [Get Function Details](/content/integrations/aws-lambda-operations#get-function-details) | Retrieves full configuration details of a specific Lambda function, including runtime, handler, IAM role, memory, timeout, and code location. |
| [Get Deployment Status](/content/integrations/aws-lambda-operations#get-deployment-status) | Retrieves the readiness of a Lambda function after creation. |
| [Update Function Configuration](/content/integrations/aws-lambda-operations#update-function-configuration) | Updates the configuration of an existing Lambda function, without redeploying code. |
| [Invoke Function](/content/integrations/aws-lambda-operations#invoke-function) | Invokes a Lambda function with a JSON payload. Supports synchronous (`RequestResponse`) and asynchronous (`Event`) invocation types. |
| [Delete Function](/content/integrations/aws-lambda-operations#delete-function) | Permanently deletes a Lambda function from your AWS account. |

<ol start="5">
<li>Select the required operation, configure the parameters, and select <strong>Save</strong> &gt; <strong>Confirm</strong>.</li>
<li>Select <strong>Execute</strong> to run the workflow.</li>
</ol>

For the complete operations parameters and output reference, see [AWS Lambda Operations Reference](/content/integrations/aws-lambda-operations).

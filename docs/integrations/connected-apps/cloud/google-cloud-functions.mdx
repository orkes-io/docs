# Google Cloud Functions Integration with Orkes Conductor

:::info Available since
- v5.3.0 and later
:::

Integrating Google Cloud Functions with Orkes Conductor lets you build workflows that interact with your Google Cloud Functions using the following operations:

- List Functions
- Invoke HTTP Function

This guide explains how to set up and use the integration. Here's an overview:

1. Get the required credentials from Google Cloud Console.
2. Configure a new Google Cloud Functions integration in Orkes Conductor.
3. Use Google Cloud Functions integration in workflows.

## Step 1: Get the Google Cloud credentials

To integrate Google Cloud Functions with Orkes Conductor, you need a Google Cloud service account with the appropriate permissions and its JSON key file.

**To create a service account and generate a key:**

1. Go to the [Google Cloud Console](https://console.cloud.google.com) and select your project.
2. Navigate to **IAM & Admin** > **Service Accounts**.
3. Select **+ Create service account**, enter a name and description, and select **Create and continue**.
4. Assign **Cloud Functions Viewer** for listing and viewing functions. Also assign **Cloud Run Viewer** if you need discovery through the Cloud Run Admin API. Cloud Run Developer alone does not grant `cloudfunctions.functions.list`.
5. Select **Continue**, then **Done**.
6. Select the newly created service account, go to the **Keys** tab, and select **Add Key** > **Create new key**.
7. Choose **JSON** as the key type and select **Create**. The key file downloads automatically.

Keep the downloaded JSON file ready; you'll need its full contents in the next step. Supply it in the integration's **Service Account JSON** secret field, not in workflow task inputs. Credential fields are handled by Conductor secret storage.

Next, enable the following APIs for the project.

**To enable the APIs for the project:**

1. Go to **APIs & Services** > **Enabled APIs & services**.
2. Select **+ Enable APIs and services**.
3. Search **Cloud Functions API** and select **Enable**.
4. Search **Cloud Run Admin API** and select **Enable**.

### API access and function invocation

The provider uses the `https://www.googleapis.com/auth/cloud-platform` OAuth scope internally. There is no Scope dropdown; IAM roles determine what the service account may do.

For HTTPS endpoints ending in `.run.app` or `.cloudfunctions.net`, the provider generates a Google ID token from the configured service-account credentials. You do not paste an ID token into this integration.

Both endpoint formats are supported:

| Function URL | ID-token audience used by the provider |
| ------------ | -------------------------------------- |
| `https://SERVICE-HASH-REGION.a.run.app` | The Cloud Run service origin. Additional paths and query parameters are excluded. |
| `https://REGION-PROJECT_ID.cloudfunctions.net/FUNCTION_NAME` | The complete function URL, including `FUNCTION_NAME`. Additional paths and query parameters are excluded. |

For an authenticated Gen 2 function, grant invocation on its backing Cloud Run service. In Cloud Shell, substitute your own values:

```bash
gcloud run services add-iam-policy-binding SERVICE_NAME \
  --project=PROJECT_ID \
  --region=REGION \
  --member="serviceAccount:SERVICE_ACCOUNT_EMAIL" \
  --role="roles/run.invoker"
```

Use the deployed service name, which may differ from the function entry point in your source code. For an authenticated 1st gen endpoint, grant **Cloud Functions Invoker** on the function instead. See [Google's invocation authentication guide](https://cloud.google.com/functions/docs/securing/authenticating).

## Step 2: Add an integration for Google Cloud Functions

After obtaining the credentials, add a Google Cloud Functions integration to your Conductor cluster.

**To create an integration:**

<ol>
<li>Go to <strong>Integrations</strong> &gt; <strong>Connected Apps</strong> from the left navigation menu on your Conductor cluster.</li>
<li>Select <strong>+ New integration</strong>.</li>
<li>In the <strong>Cloud</strong> section, choose <strong>Google Cloud Functions</strong>.</li>
<li>Select <strong>+ Add</strong> and enter the following parameters:</li>
</ol>

| Parameter | Description | Required/Optional |
| --------- | ----------- | ----------------- |
| Integration name | A name for the integration. | Required. |
| Service Account JSON | Paste the full contents of the Google Cloud service account key JSON file downloaded in [Step 1](/content/integrations/google-cloud-functions#step-1-get-the-google-cloud-credentials). | Required. |
| Default Project ID | The default Google Cloud Project ID to use when a project ID is not explicitly provided in a workflow task. | Optional. |
| Default Location | The default region for the cloud function. For example: **us-central1**. | Optional. |
| Default Function URL | The default HTTP trigger URL to use when the function URL is not explicitly provided in a workflow task. | Optional. |
| Description | A description of the integration. | Required. |

<ol start="5">
<li>(Optional) Toggle the <strong>Active</strong> button off if you don't want to activate the integration instantly.</li>
<li>Select <strong>Save</strong>.</li>
</ol>

## Step 3: Use Google Cloud Functions integration in workflows

Once the integration is ready, this can be used directly within the workflows.

**To use Google Cloud Functions integration in a workflow:**

<ol>
<li>Go to <strong>Definitions</strong> &gt; <strong>Workflow</strong> from the left navigation menu on your Conductor cluster.</li>
<li>Select <strong>+ Define workflow</strong>.</li>
<li>In your workflow, select the (<strong>+</strong>) icon and select <strong>Connected Apps</strong>.</li>
<li>In <strong>Add Task</strong> panel on the right, search for <strong>Google Cloud Functions</strong>, and select the integration created in <a href="/content/integrations/google-cloud-functions#step-2-add-an-integration-for-google-cloud-functions">Step 2</a>.</li>
</ol>

The following operations are available for use with this integration.

| Operation | Description |
| --------- | ----------- |
| [List Functions](/content/integrations/google-cloud-functions-operations#list-functions) | Lists serverless functions in a project and location, including 1st gen, 2nd gen, and Cloud Run functions. |
| [Invoke HTTP Function](/content/integrations/google-cloud-functions-operations#invoke-http-function) | Invokes an HTTP-triggered Google Cloud Function with an optional JSON payload. |

<ol start="5">
<li>Select the required operation, configure the parameters, and select <strong>Save</strong> &gt; <strong>Confirm</strong>.</li>
<li>Select <strong>Execute</strong> to run the workflow.</li>
</ol>

For the complete operations parameters and output reference, see [Google Cloud Functions Operations Reference](/content/integrations/google-cloud-functions-operations).

## Troubleshooting

- **403 on List Functions:** The service account needs `cloudfunctions.functions.list`, such as through Cloud Functions Viewer. A Cloud Run role alone does not provide this permission.
- **401/403 on invocation:** Verify the invocation role on the deployed function or backing Cloud Run service, the service-account identity, and the function URL. A different OAuth scope cannot replace an invocation permission or correct a wrong ID-token audience.
- **Wrong function name or URL:** Use the deployed name and URL, not the handler's entry-point name. Cloud Functions URLs include the function-name path; Cloud Run URLs identify the service in the hostname.

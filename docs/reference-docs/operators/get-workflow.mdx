# Get Workflow

The Get Workflow task retrieves the details of a workflow execution using its workflow ID.

:::note
The Get Workflow task succeeds only if the user who started the workflow has at least read permission on the target workflow's definition. Otherwise, the task fails with:

```
User doesn't have permission to read the workflow with ID: <WORKFLOW-ID>
```
:::

## Task parameters

Configure these parameters for the Get Workflow task.

| Parameter     | Description                                                                                                                                                                                                | Required/ Optional |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| inputParameters. **id** | The ID of the workflow execution to retrieve. It can be [passed as a dynamic variable](/developer-guides/passing-inputs-to-task-in-conductor). <br/><br/>If the ID is missing or blank, the task fails with `Missing/Blank 'id' in input parameters`. If no workflow exists with the ID, the task fails with `Wrong Workflow id`. | Required. |
| inputParameters. **includeTasks** | Whether to include the task details of the workflow execution in the output. The value must be a boolean (`true` or `false`), not a string. The default value is `true`. | Optional. |

The following are generic configuration parameters that can be applied to the task and are not specific to the Get Workflow task.

<details markdown="1">
<summary>Other generic parameters</summary>

Here are other parameters for configuring the task behavior.

| Parameter | Description | Required/ Optional | 
| --------- | ----------- | ----------------- | 
| optional | Whether the task is optional. <br/><br/>If set to `true`, any task failure is ignored, and the workflow continues with the task status updated to `COMPLETED_WITH_ERRORS`. However, the task must reach a terminal state. If the task remains incomplete, the workflow waits until it reaches a terminal state before proceeding. | Optional. | 

</details>

## Task configuration

This is the task configuration for a Get Workflow task.


```json
{
  "name": "get_workflow",
  "taskReferenceName": "get_workflow_ref",
  "inputParameters": {
    "id": "<WORKFLOW-ID>",
    "includeTasks": true
  },
  "type": "GET_WORKFLOW"
}
```

## Task output

The Get Workflow task returns the execution details of the specified workflow in the `workflow` object. This includes fields such as `status`, `input`, `output`, and `workflowDefinition`. If `includeTasks` is `true`, it also includes the `tasks` array. For example, use `${get_workflow_ref.output.workflow.status}` to reference the workflow status in a later task.

## Examples

Here are some examples for using the Get Workflow task.

<details markdown="1">
<summary>Using the Get Workflow task in a workflow</summary>

The following example demonstrates how to configure a workflow that retrieves the details of another workflow execution.

**To create a workflow:**

<ol>
<li>Go to <strong>Definitions</strong> &gt; <strong>Workflow</strong>, from the left navigation menu on your Conductor cluster.</li>
<li>Select <strong>+ Define workflow</strong>.</li>
<li>In the <strong>Code</strong> tab, paste the following workflow definition:</li>
</ol>

```json
{
 "name": "GetWorkflowDemo",
 "description": "Sample Workflow",
 "version": 1,
 "tasks": [
   {
     "name": "get_workflow",
     "taskReferenceName": "get_workflow_ref",
     "inputParameters": {
       "id": "${workflow.input.workflowId}",
       "includeTasks": true
     },
     "type": "GET_WORKFLOW"
   }
 ],
 "inputParameters": [
   "workflowId"
 ],
 "schemaVersion": 2
}
```

<ol start="4">
<li>Select <strong>Save</strong> &gt; <strong>Confirm</strong>.</li>
</ol>

**To run the workflow:**

<ol>
<li>Go to the <strong>Run</strong> tab, and enter the <strong>Input params</strong>, replacing <code>&lt;WORKFLOW-ID&gt;</code> with the ID of an existing workflow execution:</li>
</ol>

```json
{
 "workflowId": "<WORKFLOW-ID>"
}
```

<ol start="2">
<li>Select <strong>Execute</strong>.</li>
</ol>

Once the workflow starts, the Get Workflow task retrieves the details of the specified workflow execution.

To verify the result, select the **Get Workflow** task in the execution view and open the **Output** tab. The output contains the workflow execution details for the provided workflow ID.

If **Include tasks** is set to true, the output also includes the list of tasks associated with the workflow execution. If set to false, only workflow-level metadata is returned.

<p><img src="/content/img/get-workflow-output.png" alt="Output of the Get Workflow task"/></p>

This allows you to inspect the current state, status, and execution details of an existing workflow from within another workflow.

</details>

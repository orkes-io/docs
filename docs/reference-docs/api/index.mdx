# API Reference

Orkes Conductor exposes public REST APIs for workflow definitions and executions, worker tasks, schedules, events, files, bulk operations, task domains, and Conductor Agents. The complete deployment-specific surface, including administration and UI-support endpoints, is available in Swagger.

## Reference conventions

- **Availability gates:** Some APIs and tasks are available only when the feature is enabled on your cluster. Contact Orkes support to enable them.
- **Deprecation:** Deprecated routes and task types are retained only for migration guidance. Use the documented replacement for new integrations.
- **Definitions vs. runtime:** Workflow and task definitions are reusable blueprints; workflow and task objects are individual execution records. See [Schemas](/content/documentation/configuration/schemas) for the field-level contract.

## Authentication

Every request to Orkes Conductor requires an `X-Authorization` header containing a valid JSON Web Token (JWT). Generate a JWT from an application's access key and secret, then send it with every API call. See [Authentication and Access Keys](/content/sdks/authentication) for how to create an application, retrieve an access key, and generate a token.

## Base URL

All API endpoints are relative to your Conductor cluster's base URL:

```
<YOUR-CLUSTER-URL>/api/
```

For example, to list all workflow definitions:

```shell
curl <YOUR-CLUSTER-URL>/api/metadata/workflow \
  -H 'X-Authorization: <YOUR-JWT>'
```

Replace `<YOUR-CLUSTER-URL>` with the URL of your cluster, and `<YOUR-JWT>` with a JWT generated from your application's access key and secret.

## Content Type

All request and response bodies use JSON. Set the following headers on requests with a body:

```
Content-Type: application/json
```

A few endpoints return plain text (for example, the workflow ID on start). These are noted in their documentation.

## Common Response Codes

| Status Code | Description |
|---|---|
| `200 OK` | Request succeeded. The response body contains the result. |
| `204 No Content` | Request succeeded but there is no response body (for example, poll with no tasks available). |
| `400 Bad Request` | Invalid request. Check your request body or parameters. |
| `404 Not Found` | The requested resource (workflow, task, definition) does not exist. |
| `409 Conflict` | Conflict with current state (for example, trying to resume a workflow that is not paused). |
| `500 Internal Server Error` | Server-side error. Retry the request, and contact Orkes support if the error persists. |

## Error Response Format

When an error occurs, the response body contains:

```json
{
  "status": 404,
  "message": "No such workflow found by name: my_workflow, version: null",
  "instance": "<SERVER-ID>",
  "retryable": false
}
```

`instance` is the name of the server that handled the request. Some errors also include a `metadata` field with extra details.

Validation errors (400) return the message and a list of the fields that failed:

```json
{
  "message": "WorkflowTask list cannot be empty",
  "validationErrors": [
    {
      "path": "tasks",
      "message": "WorkflowTask list cannot be empty"
    }
  ]
}
```

Some APIs, such as those for applications and users, return only a `message` field.

## Quick Start

Register a workflow definition, start it, and check its status in three commands:

```shell
# 1. Register a workflow definition
curl -X POST '<YOUR-CLUSTER-URL>/api/metadata/workflow' \
  -H 'X-Authorization: <YOUR-JWT>' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "hello_workflow",
    "version": 1,
    "tasks": [
      {
        "name": "hello_task",
        "taskReferenceName": "hello_ref",
        "type": "HTTP",
        "inputParameters": {
          "http_request": {
            "uri": "https://jsonplaceholder.typicode.com/posts/1",
            "method": "GET"
          }
        }
      }
    ],
    "schemaVersion": 2
  }'

# 2. Start a workflow execution
WORKFLOW_ID=$(curl -s -X POST '<YOUR-CLUSTER-URL>/api/workflow/hello_workflow' \
  -H 'X-Authorization: <YOUR-JWT>' \
  -H 'Content-Type: application/json' \
  -d '{}')
echo "Started workflow: $WORKFLOW_ID"

# 3. Check workflow status
curl "<YOUR-CLUSTER-URL>/api/workflow/$WORKFLOW_ID" \
  -H 'X-Authorization: <YOUR-JWT>'
```

## Swagger UI

The Swagger UI at `<YOUR-CLUSTER-URL>/swagger-ui/index.html` provides an interactive API explorer where you can try endpoints directly from your browser.

## SDKs

For programmatic access, use one of the official [Conductor SDKs](/content/sdks/sdk-index), which wrap these REST APIs with language-native interfaces for Java, Python, Go, JavaScript, C#, Ruby, and Rust.
